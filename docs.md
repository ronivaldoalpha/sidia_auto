DICIONÁRIO DE TABELAS E COLUNAS Tabela: dbo.tblTransaction (Origem dos Eventos de Acesso) Tabela nativa do sistema Vault Site. Cada registro representa uma passagem ou evento de acesso. Coluna Tipo de Dado Significado / Uso no App TrDateTime datetime Data e hora exata em que o acesso ocorreu. CardNo varchar(16) Número do cartão aproximado na catraca/porta. TrCardID varchar(100) ID interno do cartão (chave de localização do usuário). UnitNo varchar(4) Identificador da unidade física do equipamento. Transaction nvarchar(50) Descrição da transação/tipo de registro (ex: Acesso Autorizado, Crachá Vencido). Chamado na lógica como @TransDesc. TrCode varchar(2) Código numérico do tipo de evento. TrController nvarchar(30) Nome/ID da controladora da porta (ex: AC-TER-08). Chamado na lógica como @TrControler. TrName nvarchar(50) Nome do usuário/titular do cartão. Tabela: dbo.tblMappingControllerCam (Mapeamento e Regras de Alerta) Tabela de de-para para vincular cada porta a até duas câmeras do VMS Digifort e definir o comportamento do evento. Coluna Tipo de Dado Significado / Uso no App Id INT (PK, Identity) Chave primária do mapeamento. UnitNo VARCHAR(4) Código da unidade. Coluna Tipo de Dado Significado / Uso no App TrController NVARCHAR(30) (Unique) Nome da controladora. Chave de ligação com tblTransaction.TrController. Cam1Nome NVARCHAR(50) Nome cadastrado para a Câmera 1 no Digifort (ex: CAM-TER-02). Cam1Server VARCHAR(15) Endereço IP do servidor Digifort da Câmera 1 (ex: 172.16.0.151 ou SRV-01). Cam2Nome NVARCHAR(50) Nome cadastrado para a Câmera 2 (Opcional / NULL). Cam2Server VARCHAR(15) Endereço IP do servidor Digifort da Câmera 2 (Opcional / NULL). dig_alerta BIT Booleano (1/0). Define o tipo de envio: 1 = Dispara Pop-up de Alerta (ACCESS_VAULT_QRU); 0 = Apenas registro silencioso no histórico (ACCESS_VAULT). Tabela: dbo.LogRequestsTransaction (Log de Falhas e Acuracidade) Tabela alimentada pelo motor assíncrono sempre que a chamada HTTP para o Digifort falha (timeout, servidor offline, etc.). Coluna Tipo de Dado Significado / Uso no App Id INT (PK, Identity) Chave primária do log. ErrorDateTime DATETIME Data e hora em que a falha de envio ocorreu. TrController NVARCHAR(30) Nome da controladora associada à falha. TargetURL VARCHAR(1000) URL HTTP enviada que sofreu rejeição ou timeout. ErrorMessage NVARCHAR(4000) Mensagem técnica de erro retornada pelo motor SQL. PayloadMessage VARCHAR(500) Dados concatenados do evento que falharam no formato: CardNo;TrName;Transaction;Tr Controller. Tabela: dbo.T_INTEGRACAO_EVENTOS (Espelhamento de Auditoria) Tabela de auditoria interna alimentada em tempo real pela trigger dbo.TRG_INSERE_INTEGRACAO_EVENTOS com os campos: Data, NomeSite, Controladora, NrCartao, TrCodigo, TrDescricao, TrNome. 2. CONEXÕES E RELACIONAMENTOS ENTRE TABELAS ● tblTransaction.TrController ➔ tblMappingControllerCam.TrController (1 para 1): ○ Relacionamento chave: O app deve associar os acessos gerados em tblTransaction com a regra de câmera/servidor gravada em tblMappingControllerCam através do nome da controladora (TrController). ● LogRequestsTransaction.TrController ➔ tblMappingControllerCam.TrController (N para 1): ○ Permite cruzar as falhas de rede com as câmeras e servidores configurados para identificar qual servidor Digifort ou porta está gerando mais instabilidades. ● tblTransaction.TrDateTime ➔ LogRequestsTransaction.ErrorDateTime (Temporal): ○ Permite correlacionar o volume total de eventos de um período em tblTransaction com a quantidade de falhas gravadas em LogRequestsTransaction para calcular a Taxa de Acuracidade (%). 3. OBJETOS DE EXECUÇÃO DO BANCO ● dbo.trg_tblTransaction_AfterInsert: Trigger na tblTransaction que captura inserções e envia para a fila. ● dbo.TransactionQueue: Fila de mensageria (Service Broker) que armazena temporariamente os pacotes XML. ● dbo.sp_ProcessarTransactionHTTP: Stored Procedure responsável por ler a fila, consultar tblMappingControllerCam, montar a requisição HTTP GET para a porta 8601 do Digifort e, em caso de erro, gravar em LogRequestsTransaction. 1. Contexto Executivo e Justificativa da Solução O projeto de integração entre o sistema de controle de acesso Vault Site e a plataforma de CFTV Digifort foi desenhado, apresentado e aprovado previamente pela equipe diretiva do cliente. O sistema Vault Site operante no cliente é uma solução considerada legada, sem suporte ativo do fabricante e desprovida de APIs ou mecanismos nativos de webhooks/triggers para integração externa. Diante dessa limitação e da necessidade crítica de sincronizar os acessos em tempo real com os 4 servidores do Digifort, optou-se pela construção de um mecanismo de integração assíncrono executado diretamente no motor do banco de dados Microsoft SQL Server. A agilidade e eficiência na condução da implantação fundamentaram-se no histórico profissional do Analista de Sistemas Ronivaldo Silva, que atuou anteriormente como técnico de manutenção no prédio Sidia SAT. Esse histórico conferiu domínio completo do cenário físico, das necessidades operacionais do cliente e do funcionamento interno do banco de dados do controle de acesso. 2. Obstáculos Identificados e Resolução Técnica em Laboratório Durante o processo de implantação no ambiente de produção, foram identificados impedimentos técnicos no ambiente original que exigiram intervenções estruturadas: ● Incompatibilidade da Versão do Banco de Dados: A instância do banco de dados operava em versão local/desatualizada (SQL Server 2008), carecendo de recursos modernos de mensageria e automação. ○ Ação Realizada: No primeiro dia de intervenção, realizou-se a atualização segura do banco de dados para o Microsoft SQL Server 2014, precedida por backup integral (Full Backup) para garantir a integridade total dos dados. ● Impedimentos de Configuração Herdados: Parametrizações prévias realizadas durante a instalação original do Vault Site bloquearam a ativação inicial das opções avançadas e dos recursos de automação OLE (Ole Automation Procedures e show advanced options). ○ Ação Realizada: Diante das falhas de execução no ambiente do cliente, a arquitetura foi replicada em ambiente de laboratório fora do prédio. O estudo detalhado em bancada identificou as travas de configuração do SQL Server e definiu a ordem correta de liberação dos componentes, permitindo o agendamento e a aplicação bem-sucedida no site. 3. Arquitetura da Solução e Componentes do Banco de Dados A solução implantada no banco DataDBEnt utiliza o recurso de mensageria nativo Service Broker para garantir processamento assíncrono, impedindo que requisições de rede afetem a velocidade de liberação das catracas. USE DataDBEnt; GO -- 2.1 Tabela de Mapeamento (De-Para) e Regra de Alerta CREATE TABLE dbo.tblMappingControllerCam ( Id INT IDENTITY(1,1) PRIMARY KEY, UnitNo VARCHAR(4) NOT NULL, TrController NVARCHAR(30) NOT NULL UNIQUE, -- Uma regra por porta Cam1Nome NVARCHAR(50) NULL, Cam1Server VARCHAR(15) NULL,  Cam2Nome NVARCHAR(50) NULL,     Cam2Server VARCHAR(15) NULL,     dig_alerta BIT NOT NULL DEFAULT 0 -- 0 = Registro Silencioso, 1 = Pop-up QRU ); GO  -- 2.2 Tabela de Auditoria e Log de Falhas de Rede CREATE TABLE dbo.LogRequestsTransaction (     Id INT IDENTITY(1,1) PRIMARY KEY,     ErrorDateTime DATETIME DEFAULT GETDATE(),     TrController NVARCHAR(30),     TargetURL VARCHAR(1000),     ErrorMessage NVARCHAR(4000),     PayloadMessage VARCHAR(500) ); GO  -- 2.3 Tabela de Espelhamento (Histórico Interno) CREATE TABLE dbo.T_INTEGRACAO_EVENTOS (     Id INT IDENTITY(1,1) PRIMARY KEY,     Data DATETIME,     NomeSite VARCHAR(50),     Controladora NVARCHAR(30),     NrCartao VARCHAR(16),     TrCodigo VARCHAR(2),     TrDescricao NVARCHAR(50),     TrNome NVARCHAR(50) ); GO  3. Arquitetura de Mensageria (Service Broker) Componentes que garantem que o sistema de acesso não trave caso o servidor Digifort fique offline. Contexto de Aplicação: Executar no banco de dados DataDBEnt. USE DataDBEnt; GO  -- 3.1 Criação do Tipo de Mensagem XML CREATE MESSAGE TYPE [TransactionMsg] VALIDATION = WELL_FORMED_XML;  -- 3.2 Criação do Contrato de Comunicação CREATE CONTRACT [TransactionContract] ([TransactionMsg] SENT BY INITIATOR);  -- 3.3 Criação da Fila de Processamento CREATE QUEUE [TransactionQueue];  -- 3.4 Criação dos Serviços de Origem e Destino CREATE SERVICE [TransactionSender] ON QUEUE [TransactionQueue]; CREATE SERVICE [TransactionReceiver] ON QUEUE [TransactionQueue] ([TransactionContract]); GO  4. O Motor Principal: Procedure de Integração HTTP Esta Stored Procedure consome a fila do Service Broker, lê as tabelas de mapeamento, define a URL baseada no nível de alerta e dispara a requisição. Contexto de Aplicação: Executar no banco de dados DataDBEnt. USE DataDBEnt; GO  CREATE OR ALTER PROCEDURE dbo.sp_ProcessarTransactionHTTP AS BEGIN     DECLARE @Dlg UNIQUEIDENTIFIER, @Body XML, @MsgTypeName SYSNAME;     DECLARE @CardNo NVARCHAR(16), @TrName NVARCHAR(50), @TransDesc NVARCHAR(50), @TrControler NVARCHAR(30);     DECLARE @MessageConcat VARCHAR(500);     DECLARE @Object INT, @HR INT;          DECLARE @Cam1Nome NVARCHAR(50), @Cam1Server VARCHAR(15);     DECLARE @Cam2Nome NVARCHAR(50), @Cam2Server VARCHAR(15);     DECLARE @DigAlerta BIT, @GlobalEvents VARCHAR(50), @URL VARCHAR(1000);      WHILE (1=1)     BEGIN         BEGIN TRANSACTION;                  -- Desenfileira a mensagem         RECEIVE TOP(1)              @Dlg = conversation_handle,              @Body = message_body,              @MsgTypeName = message_type_name          FROM dbo.TransactionQueue;                  IF @@ROWCOUNT = 0 BEGIN ROLLBACK; BREAK; END          IF @MsgTypeName = 'TransactionMsg'         BEGIN             -- Deserializa o XML             SET @CardNo = @Body.value('(/TransactionData/CardNo)[1]', 'NVARCHAR(16)');             SET @TrName = @Body.value('(/TransactionData/TrName)[1]', 'NVARCHAR(50)');             SET @TransDesc = @Body.value('(/TransactionData/Transaction)[1]', 'NVARCHAR(50)');             SET @TrControler = @Body.value('(/TransactionData/TrControler)[1]', 'NVARCHAR(30)');              SET @MessageConcat = ISNULL(@CardNo,'') + ';' + ISNULL(@TrName,'') + ';' + ISNULL(@TransDesc,'') + ';' + ISNULL(@TrControler,'');              -- Consulta Regras de Roteamento             SELECT                  @Cam1Nome = Cam1Nome, @Cam1Server = Cam1Server,                 @Cam2Nome = Cam2Nome, @Cam2Server = Cam2Server,                 @DigAlerta = dig_alerta             FROM dbo.tblMappingControllerCam             WHERE TrController = @TrControler;              IF @@ROWCOUNT > 0             BEGIN                 -- Regulação Final do Alerta (QRU = Pop-up)                 IF ISNULL(@DigAlerta, 0) = 1 SET @GlobalEvents = 'ACCESS_VAULT_QRU';                 ELSE SET @GlobalEvents = 'ACCESS_VAULT';                  -- ENVIO CÂMERA 1                 IF @Cam1Server IS NOT NULL AND @Cam1Nome IS NOT NULL                 BEGIN                     SET @URL = 'http://' + @Cam1Server + ':8601/Interface/GlobalEvents/TriggerGlobalEvent?Event=' + @GlobalEvents + '&OverrideShowObjects=1;' + @Cam1Nome + '&Message=' + @MessageConcat;                     BEGIN TRY                         EXEC @HR = sp_OACreate 'MSXML2.ServerXMLHTTP', @Object OUT;                         IF @HR <> 0 THROW 50001, 'Erro criar obj OLE', 1;                         EXEC @HR = sp_OAMethod @Object, 'open', NULL, 'GET', @URL, 'false';                         IF @HR <> 0 THROW 50002, 'Erro OPEN', 1;                         EXEC @HR = sp_OAMethod @Object, 'send';                         IF @HR <> 0 THROW 50003, 'Erro SEND (Rede)', 1;                         EXEC sp_OADestroy @Object;                     END TRY                     BEGIN CATCH                         IF @Object IS NOT NULL EXEC sp_OADestroy @Object;                         INSERT INTO dbo.LogRequestsTransaction (TrController, TargetURL, ErrorMessage, PayloadMessage)                         VALUES (@TrControler, @URL, ERROR_MESSAGE(), @MessageConcat);                     END CATCH                 END                  -- ENVIO CÂMERA 2                 IF @Cam2Server IS NOT NULL AND @Cam2Nome IS NOT NULL                 BEGIN                     SET @URL = 'http://' + @Cam2Server + ':8601/Interface/GlobalEvents/TriggerGlobalEvent?Event=' + @GlobalEvents + '&OverrideShowObjects=1;' + @Cam2Nome + '&Message=' + @MessageConcat;                     BEGIN TRY                         SET @Object = NULL;                         EXEC @HR = sp_OACreate 'MSXML2.ServerXMLHTTP', @Object OUT;                         IF @HR <> 0 THROW 50001, 'Erro criar obj OLE', 1;                         EXEC @HR = sp_OAMethod @Object, 'open', NULL, 'GET', @URL, 'false';                         IF @HR <> 0 THROW 50002, 'Erro OPEN', 1;                         EXEC @HR = sp_OAMethod @Object, 'send';                         IF @HR <> 0 THROW 50003, 'Erro SEND (Rede)', 1;                         EXEC sp_OADestroy @Object;                     END TRY                     BEGIN CATCH                         IF @Object IS NOT NULL EXEC sp_OADestroy @Object;                         INSERT INTO dbo.LogRequestsTransaction (TrController, TargetURL, ErrorMessage, PayloadMessage)                         VALUES (@TrControler, @URL, ERROR_MESSAGE(), @MessageConcat);                     END CATCH                 END             END         END          END CONVERSATION @Dlg;         COMMIT TRANSACTION;     END END; GO  -- 4.2 Vincular a Procedure à Fila para execução automática ALTER QUEUE dbo.TransactionQueue WITH ACTIVATION (     STATUS = ON,     PROCEDURE_NAME = dbo.sp_ProcessarTransactionHTTP,     MAX_QUEUE_READERS = 5,     EXECUTE AS OWNER ); GO  5. Gatilhos (Triggers) de Acionamento Gatilhos inseridos na tabela tblTransaction nativa do Vault Site para disparar o motor. Contexto de Aplicação: Executar no banco de dados DataDBEnt. USE DataDBEnt; GO  -- 5.1 Trigger de Envio para a Fila HTTP CREATE OR ALTER TRIGGER dbo.trg_tblTransaction_AfterInsert ON dbo.tblTransaction AFTER INSERT AS BEGIN     SET NOCOUNT ON;     DECLARE @Handle UNIQUEIDENTIFIER;     DECLARE @Msg XML;      -- Empacota dados em XML     SET @Msg = (         SELECT CardNo, TrName, [Transaction], TrControler, UnitNo, TrCode         FROM inserted         FOR XML PATH('TransactionData'), TYPE     );      -- Envia para o Service Broker     BEGIN DIALOG @Handle         FROM SERVICE [TransactionSender]         TO SERVICE 'TransactionReceiver'         ON CONTRACT [TransactionContract]         WITH ENCRYPTION = OFF;      SEND ON CONVERSATION @Handle MESSAGE TYPE [TransactionMsg] (@Msg); END; GO  -- 5.2 Trigger de Auditoria Interna (Espelhamento) CREATE OR ALTER TRIGGER dbo.TRG_INSERE_INTEGRACAO_EVENTOS  ON dbo.tblTransaction AFTER INSERT AS BEGIN     SET NOCOUNT ON;     INSERT INTO dbo.T_INTEGRACAO_EVENTOS (Data, NomeSite, Controladora, NrCartao, TrCodigo, TrDescricao, TrNome)     SELECT i.TrDateTime, 'Sidia_SAT', i.TrControler, i.CardNo, i.TrCode, i.[Transaction], i.TrName      FROM inserted i; END; GO  Regulação Final e Processo de Replicação Para replicar este processo integralmente em um novo servidor ou após uma formatação: 1. Janela de Manutenção: Garanta que o sistema de acesso (Vault Site) esteja paralisado durante a execução do Passo 1, pois a ativação do Service Broker requer acesso exclusivo ao banco (ROLLBACK IMMEDIATE). 2. Ordem de Execução: É imperativo que os scripts sejam executados na exata ordem numérica apresentada neste documento (1 a 5). 3. Validação de OLE: Após o Passo 1, execute EXEC sp_configure 'Ole Automation Procedures';. O valor na coluna run_value DEVE ser 1. 4. Carga Inicial: O sistema não enviará eventos para o Digifort até que a tabela tblMappingControllerCam seja populada. Para iniciar a comunicação, insira as regras: INSERT INTO dbo.tblMappingControllerCam (UnitNo, TrController, Cam1Nome, Cam1Server, dig_alerta) VALUES ('0001', 'AC-TER-08', 'CAM-TER-02', '172.16.0.151', 1); 5. Teste de Estresse de Fila: Faça uma leitura simples executando SELECT * FROM dbo.TransactionQueue;. Se houverem muitos registros parados aqui, a procedure de integração (sp_ProcessarTransactionHTTP) pode ter sofrido um erro fatal que destivou a fila. Para reativar, re-execute o comando ALTER QUEUE localizado no script 4.2.
